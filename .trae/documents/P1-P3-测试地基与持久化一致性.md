# P1 / P2 / P3：测试地基、持久化一致性、两处信息补全

## Context（为什么做）

用户要求推进 P1、P2、P3（P0 的签名与 Thread entitlement 申请推迟到周一）。这三项的动机不同：

- **P1**：项目**没有测试 target，编译是唯一回归防线**。而最近修掉的几类 bug 恰好都是"能编译、值却是错的"——OTA `UpdateState` 从 3 开始整体错位一格、`ClusterCatalog` 里 0x2F 属性名整体错位约 3 格、`DeviceTypeList` 是结构体数组却被当成数值数组读。这些全是纯函数，可单测。P1 的目的不是补覆盖率，而是**把已踩过的坑钉死**。
- **P2**：持久化普查发现的具体缺口（详见下）。
- **P3**：两处"有数据但没显示"的可辨识性问题。

**一条重要修正**：P2 原列表里的"设备记录与 fabric 对账"**不可实现**。`MTRDeviceControllerFactory.knownFabrics`（[MatterManager.swift:177](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/MatterManager.swift#L177)）返回的是 **fabric 列表**，不是节点列表；Matter.framework 没有暴露"本机已配网 nodeID 集合"。因此 `DeviceRegistry` 本身就是 nodeID 的唯一事实来源，无法自动对账，本计划**不做**这件事（也不做任何"自动删除残留记录"的尝试）。

## P1 — 引入测试 target + 首批纯逻辑用例

**工程改动**（[project.yml](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/project.yml)）：在 `targets:` 下新增测试 target。app target 的 `sources` 只有 `Sources`（第 23-24 行），所以仓库根新建的 `Tests/` **不会**被 app target 自动吸入，无需排除规则。

```yaml
  MatterExplorerTests:
    type: bundle.unit-test
    platform: iOS
    deploymentTarget: "27.0"
    sources:
      - path: Tests
    dependencies:
      - target: MatterExplorer
    settings:
      base:
        PRODUCT_BUNDLE_IDENTIFIER: com.example.MatterExplorerTests
        GENERATE_INFOPLIST_FILE: YES
        TEST_HOST: "$(BUILT_PRODUCTS_DIR)/MatterExplorer.app/MatterExplorer"
        BUNDLE_LOADER: "$(TEST_HOST)"
```

测试框架用 **Swift Testing**（`import Testing`，Xcode 27 原生支持），测试通过 `@testable import MatterExplorer` 访问 app 模块。

**跑法（需先确认 scheme 名）**：工程里目前**没有任何 .xcscheme 文件**（`xcshareddata/xcschemes` 不存在），现有 `-scheme MatterExplorer` 是 xcodebuild 自动创建的。所以：
1. 先 `xcodegen generate`，再 `xcodebuild -list -project MatterExplorer.xcodeproj`；
2. 若列表里出现测试 scheme → 用 `-scheme MatterExplorerTests test`；
3. **若没有出现** → 在 `project.yml` 里补一个显式 `schemes:` 块（app scheme 的 build/run + test 指向 `MatterExplorerTests`）后重新 generate。这是一个明确的兜底分支，不要猜。

## P2 — 持久化一致性的三项（不含对账）

**1. 统一"缓存目录解析"，并让降级可见**
现在同一段"优先 Library、失败退化到 temporaryDirectory"的逻辑抄了三份：[OTAImageStore.swift:61-66](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/OTAImageStore.swift#L61-L66)、[PAAStore.swift:32-37](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/PAAStore.swift#L32-L37)、[DCLCatalogStore.swift:134-142](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/DCLCatalogStore.swift#L134-L142)。新增一个共享入口（`Sources/Infra/AppDirectories.swift`，沿用 Infra 层的定位）提供两件事：
- `cacheSubdirectory(_ name: String) -> URL`：统一解析 + 建目录；
- 退化到 `temporaryDirectory` 时**记一条 warning 日志**（当前是静默退化，缓存随时可能被系统清掉，用户毫无察觉）。

**明确不动**：`MatterManager` 的 `MatterStore` 目录（[MatterManager.swift:29-33](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/MatterManager.swift#L29-L33)）没有退化逻辑——它是 fabric 状态，退化到临时目录意味着数据可能被清空，**保持现状，不纳入统一**。

**2. 缓存占用可见（不做自动淘汰）**
新增纯函数统计目录占用字节（放在 `AppDirectories` 里），设置页「参考数据」分区加一行 `LabeledContent` 显示三个缓存目录的合计占用（复用 `Int.byteText`，[ByteText.swift](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/ByteText.swift)），footer 说明"不做自动淘汰，可在对应页面删除（OTA 镜像库 / PAA 证书 / DCL 恢复随包数据）"。
**不做**：OTA 镜像与 PAA 证书的自动淘汰——静默删掉用户导入的固件或证书是不可接受的。

**3. `DeviceRegistry` 增加 schema 版本号**
[DeviceRegistry.swift:230-273](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/DeviceRegistry.swift#L230-L273) 目前只有一次性的 `commissionedNodes` → `deviceRecords` 迁移，没有版本概念。新增 `deviceRecordsSchemaVersion`（当前 = 1）：每次写入一并落盘；加载时缺失按 1 处理并回写；**读到比当前支持更高的版本时保留原数据不解析替换，只记一条 warning**（避免未来版本降级时误清用户数据）。

**4. 派生字段加注释（不改行为）**
`setNetworkKind` / `setEndpointCount`（[DeviceRegistry.swift:203-214](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/DeviceRegistry.swift#L203-L214)）写入的是**上次观测到的推断值**（网络类型来自 `inferredKind`）。行为不变，只补 doc 注释说明它们不是权威值、实时以读取结果为准，防止后人误当事实来源。

## P3 — 两处信息补全

**1. Fabric 卡片的厂商名**
[MatterManager.swift:162](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/MatterManager.swift#L162) 的 `vendorText` 现在是 `"VID 0x1349"`。改为复用现成的 `MatterVendorCatalog.name(for:)`（设备列表与设备记录已在用它把 VID 翻成厂商名）：查到厂商名 → `"Apple Inc. · VID 0x1349"`，查不到 → 原样退化为 `"VID 0x1349"`。
同时给卡片头部的该 `Text`（[ControllerDiagnosticsView.swift:76-78](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Features/Settings/ControllerDiagnosticsView.swift#L76-L78)）加 `.lineLimit(1)`，避免长厂商名把一行 header 撑成两行。

**2. 设置页「网络」分区显示 Thread 凭据可用性**
[SettingsView.swift:57-65](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Features/Settings/SettingsView.swift#L57-L65) 的「网络」分区目前只有一个入口，没有任何可用性提示，用户必须先点进去才知道读不了。给该 Section 加 footer，按 [ThreadCapability](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Core/ThreadCredentialProvider.swift#L25-L36) 分支：
- `isSupported == false` → `ThreadCapability.unavailableMessage`（"模拟器不支持读取系统 Thread 凭证，请在真机验证。"）；
- `isSupported == true` → 说明凭证来自系统已保存的网络、用于 Thread 配网与排查。
**只在不支持时给降级结论**，真机上一律写"可用"是假承诺（真机缺 entitlement 时同样读不到），所以不写"可用"。
