# 设备特征展示实现方案

## Context

当前「设备」页只把节点当作一条记录来展示：`DeviceRow` 显示 displayName、在线状态、节点 ID、VID/PID、DCL 厂商产品名、网络类型、端点数。用户看不出这台设备**能做什么、现在读数是多少**——一台空气检测仪和一只灯在列表里长得几乎一样。

目标是让设备页像米家 / SmartThings 那样把节点当作「设备」呈现其特征：空气检测仪直接显示温度、湿度、PM2.5 读数；灯显示开关、亮度、色温；插座显示开关状态。详情页可对控制类特征直接操作（开关、调亮度），不必再跳到「设备控制」页。

已确认的范围决策：

1. **展示位置**：列表行加一行关键读数摘要 + 详情页新增「设备特征」分区。
2. **交互**：详情页特征卡片可交互；列表行只读。
3. **刷新**：详情页订阅实时更新；列表只读一次并缓存，不订阅。
4. **首批覆盖**：传感器读数（温度、湿度、PM2.5、CO2、空气质量、照度、占用、门磁/布尔状态）＋ 控制状态（开关、亮度、色温、开合位置）。

## 方案

### 1. 特征模型：新增独立的 `DeviceTrait`

不扩展 `ControlCapability`。后者的语义是「可控能力」，驱动控制页生成控件与命令；传感器不可控，混进去会污染 `capabilities(from:)` 与 `stateAttributes`，并迫使控制页处理无控件的 case。特征是「展示单元」，与属性是一对多关系，还要表达「不可用」。

新建 `Sources/Core/DeviceTraitCatalog.swift`：

```swift
enum DeviceTraitKind: String, Sendable { case reading, control }

enum DeviceTrait: String, CaseIterable, Identifiable, Sendable {
    case temperature, humidity, pm25, co2, airQuality, illuminance, occupancy, booleanState
    case onOff, brightness, colorTemperature, windowCovering

    var clusterID: UInt32
    var attributeKeys: [ControlAttributeKey]      // 主属性在前
    var primaryKey: ControlAttributeKey
    var controlCapability: ControlCapability?     // 非 nil 即可交互
    var kind: DeviceTraitKind
    var title: String
    var systemImage: String
    var listPriority: Int
}

enum DeviceTraitCatalog {
    static let traitForCluster: [UInt32: DeviceTrait]
    static func traits(from clusterIDs: [UInt32]) -> [DeviceTrait]
    /// 纯函数：把原始值转成展示文本，便于 Preview 覆盖边界
    static func reading(_ trait: DeviceTrait, values: [ControlAttributeKey: MatterScalar],
                        endpointID: UInt16) -> TraitReading
}
```

特征表（cluster / 主属性 / 可控 / 标题 / Symbol / 换算）：

| 特征 | 集群 | 主属性 | 可控 | 标题与符号 | 换算与显示 |
|---|---|---|---|---|---|
| temperature | 0x0402 | 0/0 | 否 | 温度 / thermometer.medium | raw/100 ℃，`%.1f ℃`；哨兵 0x8000 → 无读数 |
| humidity | 0x0405 | 0/0 | 否 | 湿度 / humidity | raw/100 %，`%.0f%%`；同上哨兵 |
| pm25 | 0x042A * | 0/0 | 否 | PM2.5 / smallcircle.filled.circle | µg/m³，`%.0f` |
| co2 | 0x040D * | 0/0 | 否 | CO₂ / lungs | ppm，`%.0f` |
| airQuality | 0x005B * | 0/0 | 否 | 空气质量 / wind | enum8 → 未知/优/良/中/差/很差/极差 |
| illuminance | 0x0400 * | 0/0 | 否 | 照度 / sun.max | 10^(v/10000) lx；v=0 → 「过暗」；>1000 → klx |
| occupancy | 0x0406 | 0/0 | 否 | 占用 / person.fill | bitmap8 bit0 → 有人 / 无人 |
| booleanState | 0x0045 * | 0/0 | 否 | 状态 / sensor.tag | bool → 开 / 关（门磁语义，文案取通用） |
| onOff | 0x06 | 0/0 | 是 | 开关 / power | 开 / 关 |
| brightness | 0x08 | 0/0 | 是 | 亮度 / sun.max | 复用 `percent(fromLevel:)` |
| colorTemperature | 0x0300 | 7 | 是 | 色温 / thermometer.sun | 以 `kelvin(fromMireds:)` 为主，附 mireds |
| windowCovering | 0x0102 | 0x0E | 是 | 开合位置 / blinds.horizontal | percent100ths/100 → %，附 OperationalStatus |

`*` 标注的 5 个集群未收录于 `ClusterCatalog.clusters`，按 Matter 1.4 规范填写，实现时必须同步补录名称表，并用集群工具页对真实设备复核后再确认。

取值降级：`.null` / `.unsupported` / 数值哨兵（温度 0x8000、照度 0）→ `isAvailable = false`，显示「—」，且**不进入列表摘要**；单属性读失败沿用现有 notices 容忍机制，不影响同端点其他特征。

### 2. 数据层：扩展 `DeviceControlService`，不新建平行服务

理由：`discoverEndpoints → discoverClusters → readScalars` 链路已带失败容忍、notices 与日志；新服务会对同一节点重复遍历端点并产生两套订阅，且 `subscriptionToken` 的单令牌设计需要统一协调。

新建 `Sources/Core/DeviceTraitSnapshot.swift`（Sendable 值类型）：

```swift
struct TraitReading: Identifiable, Sendable, Hashable {
    let trait: DeviceTrait; let endpointID: UInt16
    let text: String; let rawText: String
    let isAvailable: Bool; let canControl: Bool
}
struct EndpointTraitSnapshot: Identifiable, Sendable {
    let endpointID: UInt16; let traits: [DeviceTrait]
    let values: [ControlAttributeKey: MatterScalar]; let notices: [String]
}
struct DeviceTraitSnapshot: Sendable {
    let nodeID: UInt64; let endpoints: [EndpointTraitSnapshot]
    let notices: [String]; let updatedAt: Date
    let summaryReadings: [TraitReading]
}
```

`DeviceControlService` 改动：

- 私有 `readStates` 的入参由 `capabilities: [ControlCapability]` 泛化为 `keys: [ControlAttributeKey]`（去重后逐个读），控制页与特征页共用，行为不变。
- 新增 `detectTraits(nodeID:completion:)`：复用同一套端点/集群遍历，改用 `DeviceTraitCatalog.traits(from:)`。
- 新增 `startTraitMonitoring(nodeID:paths:onUpdate:onState:)` + `stopMonitoring(role:)`：把 `subscriptionToken: String?` 改为 `subscriptionTokens: [String: String]`（role = `"control"` / `"traits"`），避免详情页与「设备控制」页同栈时互相取消订阅；保留无参 `stopMonitoring()` 清全部以兼容现有调用。
- 新增 `static func summaryReadings(from:) -> [TraitReading]`：排序键 `(kind == .reading ? 0 : 1, listPriority)`，取前 3。

列表缓存：新建内存缓存 `DeviceTraitCache`（`final class @unchecked Sendable` + `NSLock`，`[UInt64: (snapshot, updatedAt)]`）。**不写 UserDefaults / DeviceRegistry**。失效条件：`updatedAt` 超过 60s，或设备刚从不可达转为可达。`DevicesViewModel.reload()` 之后串行（并发 1）对「未缓存 / 已过期且可达」的设备补读；`removeRecord` 时清对应项；详情页控制成功后可回写。

详情页订阅：`paths = snapshot.endpoints.flatMap { $0.traits.flatMap(\.attributeKeys).map { ControlAttributePath(endpointID:, key:) } }`；`DeviceTraitViewModel` 收到快照后订阅，`onAppear` 幂等重启、`onDisappear` 取消。注意 push「设备控制」页会触发详情页 `onDisappear`、返回时 `onAppear` 重订，因此**不能用只跑一次的 `.task` 管订阅**。delegate 去重由 `ClusterToolService` 现有的 token→handle 表保证。

### 3. 界面

**列表行**（`DeviceRow` 内加一行）：有缓存时用 `ViewThatFits(in: .horizontal)` 依次尝试 3 / 2 / 1 个 `Label`，`.font(.caption)`、`.lineLimit(1)`、次级色；**无缓存时不显示占位**（避免闪烁）；全部不可用 → 不显示，回落到现有「网络 / 端点」行。排序：优先首个读数，其次 onOff，再按 `listPriority`。只读，不加手势。

**详情页「设备特征」分区**：插在 `toolEntrySection` 之后、`identitySection` 之前。多端点时按端点分 Section（header「端点 N」，footer 放 notices）。卡片用 `LazyVGrid(.adaptive(minimum: 150), spacing: 12)`：图标 + 标题（caption）+ 数值（title2）+ 单位；不可用显示「—」。可交互卡片内嵌控件：开关用 `Toggle().labelsHidden()`，亮度 / 色温 / 开合用 `Slider`，沿用 `DeviceControlViewModel` 的 drafts / pending / 失败回滚；失败用 `.alert("操作失败")` 弹出 `viewModel.message`（List 的 footer 不显眼）。

**控件复用（最小改动）**：新建 `Sources/Features/Devices/ControlWidgets.swift`，把 `DeviceControlView` 的 `onOffControl` / `identifyControl` / `brightnessControl` / `colorTemperatureControl` / `liftControl` 提取为 `TraitControlWidget(nodeID:capability:snapshot:viewModel:)`，`DeviceControlView` 改为调用它，两条路径共用同一份逻辑。详情页由 `DeviceTraitViewModel` 组合一个 `DeviceControlViewModel`：把特征快照映射成 `EndpointControlSnapshot`（capabilities 由 `trait.controlCapability` 推导）喂给 `control.detection` 并调 `syncDrafts()`（需从 private 改为 internal）。

**与现有「设备控制」页的关系**：确实部分重复。保留原页作为「完整控制面板」（识别闪烁、原始值、命令结果、调试用），入口文案改为「完整控制面板（含识别闪烁与原始值）」。

已知限制（沿用现有行为，本次不修）：`discoverEndpoints` 基于端点 0 的 PartsList，不含端点 0 自身，若某功能只落在端点 0 会漏读。

端到端验证步骤（已知已配网设备：VID 4476 / PID 12289，node 11993703908524598127）：

1. **列表摘要**：进入设备 Tab，该行应在约 1–2s 后出现读数摘要（首次无缓存）。停留列表期间日志中**不应**出现「订阅已建立」——证明列表没有订阅。
2. **详情页实时**：进入设备详情，应出现「设备特征」分区，日志出现「订阅已建立（属性数 = 特征属性数）」；从设备端物理改变状态 → 日志出现「订阅属性更新」→ 卡片数值实时变化。
3. **订阅生命周期**：从详情页进入「设备控制」页 → 日志出现详情页的「订阅已取消」；返回详情页 → 再次「订阅已建立」。反复进出不应出现重复订阅或泄漏。
4. **控制类交互**：若该设备是灯 / 插座，卡片上的开关可点，日志「控制命令成功」，设备实际响应；失败时应弹出 alert 且状态回滚。
5. **无真实传感器时的替代验证**：先用「集群工具」页对端点逐簇读 `ServerList` 与单属性，确认设备实际支持哪些簇（读不到即设备不支持，非代码问题）；用其订阅功能复核兴趣路径写法；用 `DeviceTraitCatalog.reading(...)` 的纯函数配合 `#Preview` 构造 `MatterScalar.number(-32768)`、`.null`、照度 0 等边界，验证格式化与降级显示。
