# 设置「控制器」模块：层次与去重

## Context（为什么改）

设置页的控制器模块目前把**同一批状态信息渲染了两遍**：

- 根页「控制器」分区（[SettingsView.swift:37-52](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Features/Settings/SettingsView.swift#L37-L52)）：控制器工厂、控制器、已配网设备 3 行状态 + 「控制器诊断」入口。
- 子页「控制器」分区（[ControllerDiagnosticsView.swift:20-33](file:///Users/peterjiang/Documents/trae_projects/MatterExplorer/Sources/Features/Settings/ControllerDiagnosticsView.swift#L20-L33)）：**同样 3 行状态**，外加控制器节点 ID 与存储目录。

用户希望的优化方向：**层次与去重**——根页负责"一眼看状态"，子页负责"看诊断细节"。属于**纯结构调整：不新增功能、不减少信息总量、不改视觉风格**。

## 变更

### 1. `Sources/Features/Settings/ControllerDiagnosticsView.swift`

`controllerSection`（L20-33）删除与根页重复的三行 `LabeledContent`：

- `控制器工厂` / `控制器` / `已配网设备` 三行整体移除。

保留并补齐节点 ID 行——因为删掉三行后，控制器未就绪时 `if let` 会产出空分区，需按**同文件既有约定**补占位（与 `storageSection` L39-45 的「存储目录未知」写法完全一致）：

```swift
if let nodeID = viewModel.status.controllerNodeID {
    copyRow("控制器节点 ID", value: "\(nodeID)", monospaced: true)
} else {
    Text("控制器节点 ID 未知")
        .font(.callout)
        .foregroundStyle(.secondary)
}
```

Section 的 header（「控制器」）与 footer（只解释节点 ID 的含义）**保持原文不变**。`copyRow` / `copyText` / 存储分区 / fabric 分区均不动。

### 2. `Sources/Features/Settings/SettingsView.swift`

`controllerSection` **不做任何改动**——它是 3 行状态摘要的唯一位置，继续保留。

仅在该分区上方的注释（L36）补一句分工说明，避免以后有人把状态行又加回子页：

```swift
/// 控制器状态摘要（唯一位置）；节点 ID、存储目录与 fabric 明细收在「控制器诊断」子页（下拉可刷新状态）。
```

## 明确不做

- 不新增操作入口（导出诊断、工厂停止/重启）；
- 不加状态色 pill / 图标；
- 不改任何 footer 文案、不改分区顺序；
- 不合并「控制器工厂」与「控制器」两行（两者语义不同：工厂进程 vs 控制器实例，合并会丢信息）。

## 验证

无新增文件，无需 `xcodegen generate`。构建：

```bash
cd /Users/peterjiang/Documents/trae_projects/MatterExplorer && xcodebuild -project MatterExplorer.xcodeproj -scheme MatterExplorer -destination 'platform=iOS Simulator,id=0C5A1561-8241-4FB1-9CEB-2A260A0F9C1D' -derivedDataPath build/DerivedData build 2>&1 | grep -E "error:|BUILD"
```

模拟器手动核对（不执行 `xcrun simctl uninstall`）：

1. 设置页「控制器」分区：仍是 3 行状态 + 「控制器诊断」入口（入口右侧仍显示「N 个 fabric」）；
2. 进入「控制器诊断」：第一分区只剩「控制器节点 ID」（可拷贝），不再出现工厂/控制器/已配网设备；
3. 「存储」与「已识别 fabric」两个分区内容与改动前完全一致；
4. 控制器未就绪时应显示「控制器节点 ID 未知」占位，而不是一个空分区。
